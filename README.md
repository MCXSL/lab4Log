# Лабораторная работа № 4 — Бинарное дерево поиска

Решение на C++17 с системой сборки CMake. Дерево реализовано самостоятельно
через узлы с полями `data`, `left`, `right`; готовые контейнеры для хранения дерева
в основной программе не используются.

## Выполненные задания

1. `contains(value)` ищет введённое с клавиатуры целое число в построенном дереве.
2. `count(value)` подсчитывает число вхождений значения.
3. `insert(value)` с политикой `DuplicatePolicy::Reject` исключает добавление повторов.
4. Ниже приведена оценка сложности поиска и других операций.

Для проверки обычного и дополнительного заданий из каждого введённого числа
одновременно строятся два независимых дерева: с повторами и без повторов.
Поиск и подсчёт выводят результаты для обоих деревьев.

## Сборка и запуск

Нужны компилятор с поддержкой C++17 и CMake версии 3.16 или выше.
Подойдут GCC, Clang или MSVC. Команды выполняются из папки проекта:

```sh
cmake -S . -B build
cmake --build build --config Release
```

Запуск в Windows при сборке Ninja или MinGW:

```powershell
.\build\lab4.exe
```

При использовании генератора Visual Studio:

```powershell
.\build\Release\lab4.exe
```

В Linux и macOS:

```sh
./build/lab4
```

В CLion достаточно открыть папку проекта, дождаться загрузки CMake и запустить
цель `lab4`. Исходники сохранены в UTF-8; в Windows программа устанавливает
UTF-8 для консоли, а для MSVC CMake включает параметр `/utf-8`.
При работе с MinGW из терминала его папка `bin` должна быть в `PATH`;
альтернативно необходимые DLL среды выполнения можно разместить рядом с EXE.

## Работа с программой

При начальном построении вводите числа через пробел или перевод строки.
Число `-1` завершает построение и на этом этапе в дерево не добавляется.
После построения программа выводит оба дерева и меню:

| Пункт | Действие |
| --- | --- |
| 1 | Вывести оба дерева |
| 2 | Найти значение в обоих деревьях |
| 3 | Подсчитать вхождения в обоих деревьях |
| 4 | Добавить число в оба дерева |
| 5 | Очистить оба дерева |
| 0 | Завершить программу |

Через пункт 4 можно добавить любое значение типа `int`, в том числе `-1`.
В дереве без повторов программа сообщает об отклонении повторного значения.
Ошибочные токены и числа вне диапазона `int` не добавляются: программа просит
повторить ввод. Конец входного потока корректно завершает программу.
Память узлов освобождается при очистке и завершении работы.

Дерево показано с поворотом на 90 градусов: корень слева, правое поддерево
сверху, левое снизу. Для чисел `2 1 3 -1` результат выглядит так:

```text
    3
2
    1
```

## Пример проверки

Введите последовательно:

```text
8 3 10 1 6 14 4 7 13 6 6 -1
3
6
2
9
4
6
3
6
0
```

После построения в обычном дереве 11 узлов, в дереве без повторов — 9.
Первый подсчёт числа `6` даёт 3 и 1 соответственно. Поиск числа `9`
сообщает об отсутствии в обоих деревьях. После добавления ещё одной `6`
подсчёт даёт 4 и 1; во втором дереве повтор отклоняется.

## Алгоритмы

При добавлении число сравнивается с текущим узлом. Меньшее значение направляется
в левое поддерево, большее — в правое. Если повторы разрешены, равное значение
тоже направляется вправо. Если повторы запрещены, при равенстве функция сразу
возвращает `false`. Когда найден пустой указатель, создаётся новый узел.

Таким образом, в каждом левом поддереве значения строго меньше значения узла,
а в правом — больше или равны ему. В дереве без повторов справа они строго больше.
В примере функции добавления из методички ветви для больших и меньших значений
переставлены относительно её текстового определения; здесь используется
порядок из определения: меньшие значения слева, большие справа.

Поиск `contains` начинается с корня. При совпадении возвращается `true`.
Если искомое значение меньше текущего, поиск продолжается слева, иначе справа.
Достижение пустого указателя означает, что значение отсутствует.

Подсчёт `count` идёт по тому же пути, но после совпадения увеличивает счётчик
и продолжает поиск справа. Слева от совпавшего узла повторов быть не может.
Если следующий узел больше искомого значения, алгоритм снова переходит влево.
Поэтому учитываются и повторы, которые расположены под более крупными узлами,
а не только цепочка непосредственно соединённых одинаковых узлов.

## Оценка сложности

Пусть `n` — число узлов, `h` — высота дерева, измеренная числом узлов на самом
длинном пути от корня до листа. Для пустого дерева `h = 0`.

| Операция | Время | Дополнительная память |
| --- | --- | --- |
| Поиск `contains` | `O(h)` | `O(1)` |
| Подсчёт `count` | `O(h)` | `O(1)` |
| Добавление `insert` | `O(h + 1)` | `O(1)` без учёта нового узла |
| Получение размера `size` | `O(1)` | `O(1)` |
| Освобождение узлов `clear` | `O(n)` | `O(h)` на стек рекурсии |

Поиск проходит только по одному пути, поэтому число сравнений ограничено
высотой. Лучший случай успешного поиска — совпадение в корне, `O(1)`.
При сбалансированной форме `h = O(log n)`, поиск занимает `O(log n)`.
В худшем случае, например после добавления отсортированных чисел, дерево
вырождается в цепочку: `h = n`, время поиска — `O(n)`.
При случайном порядке различных ключей ожидаемое время поиска — `O(log n)`.
Автоматической балансировки в этой реализации нет, поэтому логарифмическое
время не гарантируется. Большое число одинаковых ключей также создаёт цепочку
в дереве с повторами.

Дерево занимает `O(n)` памяти. Вывод обходит каждый узел и печатает отступ
по его глубине: время `O(n + сумма глубин)`, до `O(n²)` для цепочки,
дополнительная память `O(h)`. Вывод и очистка рекурсивны, поэтому для очень
глубоких деревьев размер стека ограничивает допустимый объём данных.

## Структура проекта и проверки

- `include/binary_search_tree.hpp` — объявление узла, дерева и операций.
- `src/binary_search_tree.cpp` — добавление, поиск, подсчёт, вывод и освобождение памяти.
- `src/main.cpp` — ввод чисел и интерактивное меню.
- `CMakeLists.txt` — сборка программы и подключение проверок к CTest.

Вывод: бинарное дерево позволяет выполнять поиск, двигаясь только по одной ветви
на каждом шаге. Скорость зависит от высоты дерева; запрет повторов реализуется
проверкой равенства во время добавления.
